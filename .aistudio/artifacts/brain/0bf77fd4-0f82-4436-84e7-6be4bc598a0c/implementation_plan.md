# Сервис бронирования ресурсов (Ruby on Rails + Vue.js + PostgreSQL)

Полная переработка проекта под классическую архитектуру многостраничного приложения (MPA) на **Ruby on Rails** с серверным рендерингом **ERB-шаблонов**, точечными реактивными виджетами на чистом **Vue.js (JavaScript)** и базой данных **PostgreSQL** (`tsrange` + `GiST`). Весь код React и TypeScript полностью удаляется.

## User Review & Critical Decisions

> [!IMPORTANT]
> Все решения согласованы с требованиями учебного курса по Ruby и архитектурой из описания проекта:

- **Подтвержденное решение 1 (Стек и запуск)**: Полное удаление TypeScript и React. Создание канонического проекта Ruby on Rails (`Gemfile`, модели ActiveRecord, контроллеры, маршруты, миграции и сиды для `bundle exec rails db:prepare` и `bundle exec rails server`) в связке с прозрачным JS-рантаймом для рендеринга тех же самых ERB-представлений и Vue.js-виджетов в живом превью AI Studio на порту 3000.
- **Подтвержденное решение 2 (Интеграция Vue.js)**: Точечное монтирование компонентов Vue.js 3 (на чистом JavaScript без Vue Router и без TypeScript) непосредственно внутри серверных ERB-шаблонов Rails для интерактивного календаря слотов, проверки доступности через Fetch API и динамического расчета стоимости.
- **Подтвержденное решение 3 (БД, Авторизация и Почта)**: Использование гема **Devise** для сессионной аутентификации, миграций **PostgreSQL** с расширением `btree_gist`, типом `tsrange` и ограничением `EXCLUDE USING gist` против двойного бронирования (овербукинга), а также **ActionMailer** (`BookingMailer`) для отправки писем подтверждения и отмены.

## 1. Overview & Core Concept

- **Назначение приложения**: Многостраничная система бронирования переговорных комнат, студийного оборудования и записи к профильным специалистам.
- **Целевая аудитория**: Пользователи и сотрудники, которым требуется наглядно проверить свободные слоты времени, рассчитать стоимость аренды и забронировать ресурс с гарантией отсутствия накладок по времени.
- **Ключевая ценность**: Сочетание надежности классического MVC-сервера на Ruby on Rails и транзакционной защиты PostgreSQL (`tsrange` exclusion constraints) с мгновенной реактивностью виджета календаря на Vue.js без перезагрузки страницы при выборе дат.

## 2. User Experience & Visual Design

- **Карта экранов и пользовательские сценарии (Rails MPA + Vue.js)**:
  1. **Главная страница и Каталог ресурсов (`ResourcesController#index`)**: Серверная страница со списком доступных объектов, фильтрацией по категориям («Все ресурсы», «Переговорные комнаты», «Оборудование», «Специалисты») и поиском.
  2. **Страница конкретного ресурса (`ResourcesController#show`)**: Детальное описание объекта, характеристики, почасовая ставка и встроенный в ERB-шаблон **интерактивный виджет Vue.js**.
  3. **Виджет календаря и слотов (Vue.js)**: При клике на дату Vue-компонент отправляет асинхронный `fetch`-запрос к JSON-эндпоинту контроллера Rails (`/api/v1/resources/:id/availability`), мгновенно отрисовывает свободные и занятые часовые слоты (09:00–21:00), проверяет отсутствие пересечений и динамически считает итоговую сумму.
  4. **Оформление и подтверждение (`BookingsController#create`)**: Отправка формы бронирования, валидация пересечений интервалов `tsrange` на стороне сервера, запись в БД, вызов `BookingMailer.confirmation_email` и переход на экран успешного бронирования.
  5. **Авторизация Devise и Личный кабинет (`BookingsController#index` / `DashboardController#index`)**: Вход/регистрация пользователя, просмотр активных и отмененных броней, статистика забронированных часов и кнопка отмены брони (`PATCH /bookings/:id/cancel`), мгновенно освобождающая слот.

- **Визуальная система и дизайн**:
  - **Эстетика**: Чистый утилитарный европейский минимализм для рабочих пространств и расписаний (светлая палитра с четкими разделителями 1px и выверенной типографикой).
  - **Цветовая палитра (60-30-10)**:

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Двойная совместимость (Локальный запуск Rails + Превью в AI Studio)**
  - *Выбранный подход*: Создание полной классической структуры Ruby on Rails (`Gemfile`, `Rakefile`, `config/`, `app/`, `db/`) для локального запуска командами `bundle exec rails db:prepare` и `bundle exec rails server`, плюс легковесный сервер превью на чистом JS, который отдает этот же интерфейс с настоящим Vue.js 3 в браузер AI Studio.
  - *Почему*: Вы получаете 100% валидный проект по предмету Ruby on Rails для защиты и запуска на своем ПК с PostgreSQL, и одновременно можете визуально проверять работу всех страниц и виджета Vue.js прямо в окне превью.
- **Решение 2: Точечный Vue.js 3 без сборщика SPA**
  - *Выбранный подход*: Инициализация компонентов Vue 3 (`createApp`) на конкретных DOM-узлах (`#vue-booking-widget`, `#vue-catalog-filter`) внутри серверных представлений Rails.
  - *Почему*: Точно соответствует архитектуре из вашего `README.md` («используется точечно для виджетов, требующих высокой реактивности, без использования Vue Router»).
- **Решение 3: Защита от овербукинга через `tsrange` и `GiST`**
  - *Выбранный подход*: В миграции PostgreSQL используется поле `booking_period tsrange` и ограничение `EXCLUDE USING gist (resource_id WITH =, booking_period WITH &&) WHERE (status = 'confirmed')`, дублируемое валидацией в модели `Booking`.
  - *Почему*: Гарантирует отсутствие пересечений времени даже при одновременных запросах в рамках транзакций БД.

### Модель данных (PostgreSQL + ActiveRecord)

1. **`User` (Devise)**:
   - Поля: `id`, `name`, `email`, `encrypted_password`, `phone`, `role`, `created_at`.
   - Связи: `has_many :bookings, dependent: :destroy`.
2. **`Resource`**:
   - Поля: `id`, `name`, `category` (`rooms`, `equipment`, `specialists`), `category_name`, `description`, `location`, `capacity`, `hourly_rate`, `amenities` (массив), `image_url`.
   - Связи: `has_many :bookings, dependent: :destroy`.
3. **`Booking`**:
   - Поля: `id`, `user_id`, `resource_id`, `starts_at`, `ends_at`, `booking_period` (`tsrange`), `total_price`, `status` (`confirmed`, `cancelled`), `purpose`, `contact_phone`.
   - Ограничение уровня БД: `add_exclusion_constraint :bookings, "resource_id WITH =, tsrange(starts_at, ends_at, '[)') WITH &&", using: :gist, where: "status = 'confirmed'"`.

### Интерактивные сценарии и обработка состояний

- **Переключение даты в виджете Vue.js**: Вызывает метод `fetchAvailability(date)`, показывает плавный индикатор загрузки слотов, запрашивает занятые интервалы у сервера и блокирует пересекающиеся часы.
- **Выбор диапазона времени**: Первый клик задает час начала, второй — час окончания. Если внутри диапазона встречается уже занятый слот, Vue-виджет мгновенно выводит предупреждение о пересечении и сбрасывает некорректный выбор.
- **Оформление и проверка на овербукинг**: При отправке формы сервер проверяет пересечение интервалов `[starts_at, ends_at)`. При успехе сохраняет бронь, формирует уведомление `BookingMailer` и перенаправляет в «Мои бронирования».
- **Управление в Личном кабинете**: Позволяет фильтровать список броней по статусу («Все», «Активные», «Отмененные»), просматривать сгенерированные письма `ActionMailer` и отменять активную бронь в один клик с немедленным освобождением слота в календаре.
